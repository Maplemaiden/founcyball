# Founcyball 正式版大纲

> 基于已验证的 MVP 手感 · 主打手机 · 目标渠道：微信小游戏  
> 版本：0.1（规划稿）

---

## 1. 一句话目标

把「俯视回合制弹球足球」做成**可长期运营的微信小游戏**：保留现有核心手感，叠球员差异、技能与连携，先单机/本地双人，再轻度社交与变现。

---

## 2. 产品定位

| 项 | 定稿 |
|----|------|
| 平台 | **微信小游戏**（主）；H5 可作次要出口 |
| 操作 | 竖屏；点选拖拽蓄力 + 副指/键位弧线 |
| 对局 | 本地双人优先；单人可对简易 AI（二期） |
| 长度 | 一局 3～8 分钟（先到 N 分） |
| 差异化 | 物理弹球手感 + 足球主题 + 轻卡牌式球员/技能 |

**不做成：** 重度联网竞技、开放世界、复杂模拟经营。

---

## 3. 技术路线

### 3.1 推荐栈

| 层 | 选择 | 说明 |
|----|------|------|
| 引擎 | **Cocos Creator 3.x** | 出微信小游戏成熟；2D 物理/UI/分包友好 |
| 语言 | TypeScript | 与现原型逻辑一一对应迁移 |
| 后端（一期可不做） | 云开发 / 自建均可 | 一期可纯本地存档 |
| 现原型 | 保留为手感沙盒 | 调参、验技能，不定时迁回正式工程 |

### 3.2 迁移原则

1. **手感参数表先行**：力度、摩擦、边线弹性、弧线 Rmin/Rmax、换手速度阈值 → 做成可配置 JSON。  
2. **物理与表现分离**：`Match / Physics / Input / Skill` 模块清晰，方便加技能不改物理内核。  
3. **资源分包**：首包只含一场基础对局；球员皮肤、音效走分包。  
4. **输入**：微信触摸多点；PC 调试保留 A/D 弧线。

### 3.3 不建议一期做的技术

- Unity（过重）  
- 实时帧同步联网对战  
- 自研完整物理引擎重写（在现有模型上扩展即可）

---

## 4. 模块划分

```
┌─────────────────────────────────────────┐
│  App 壳（登录、大厅、设置、合规页）        │
├──────────────┬──────────────────────────┤
│  大厅 / 编队  │  对局（核心）              │
│  球员图鉴     │  Match 状态机             │
│  技能装备     │  Input（蓄力/弧线）        │
│  简单商店     │  Physics（滑/撞/门）       │
│              │  SkillRuntime             │
│              │  ComboDetector            │
│              │  HUD / 结算               │
├──────────────┴──────────────────────────┤
│  存档 / 配置表 / 音效 UI / 分析埋点        │
└─────────────────────────────────────────┘
```

| 模块 | 职责 |
|------|------|
| Match | 回合、比分、胜负、开球重置 |
| Physics | 圆碰撞、摩擦、边线/球门、弧线转向 |
| Input | 选人、拖拽力度、副指弧线 |
| Roster | 上场 3 人、属性、技能槽 |
| SkillRuntime | 技能释放时机、消耗、改参数/加 buff |
| ComboDetector | 连携条件检测与触发 |
| Meta | 解锁、货币、图鉴（一期可极简） |

## 5. 核心玩法（继承 MVP）

保持不变的底层规则：

- 俯视、竖屏球场（105×68 比例），球门宽约底线 2/5，向外球门槽  
- 各 3 圆形球员 + 1 球；回合制，一次一击  
- 拖拽蓄力（反方向弹出）；弧线绕圆，半径有下限  
- 虚线预览（疏密=力度；一次折射；显示约 2/3）  
- 全体低于换手速度即可切换回合  
- 球整体越过门线得分  

正式版在此之上只做：**数值分化 + 技能 + 连携 + 内容包装**。

## 6. 球员系统

### 6.1 属性（可见四维，0～100；50≈基准）

| 属性 | 影响 |
|------|------|
| 力量 Power | 最大初速度倍率 |
| 弧线 Curve | 更小的可达 Rmin、更快拧弯 |
| 控停 Grip | 摩擦偏高，更早停下（防守向） |
| 冲撞 Weight | 质量，碰撞推人更硬 |

体型不做可见参数（全局统一半径）。体力等资源维留给技能期。  
正式版用**倍率乘在现有物理常数上**（见 `js/data/physics.js`）。

### 6.2 定位模板（便于做卡）

- 前锋：高力量、中弧线  
- 中场：高弧线、中力量  
- 后卫：高冲撞、高稳停  
- 门将型（可选）：更大半径或禁区特效——一期可不做专属门将  

### 6.3 编队

- 每局仍 **上场 3 人**  
- 解锁更多球员后，大厅选 3 人出战  
- 一期：固定几套「新手套装」即可，不必大卡池  

---

## 7. 技能系统

### 7.1 设计原则

- 技能优先 **改参数 / 加一次性效果**，少改胜负规则  
- 每名球员 **1 个主动**（或 1 被动 + 可选主动）  
- 每局限次（如 1～2 次），避免每回合必放  

### 7.2 技能类型（第一期候选）

| 类型 | 示例 | 实现难度 |
|------|------|----------|
| 强化击打 | 本击力量 +20% | 低 |
| 锐利弧线 | 本击 Rmin 再降低 | 低 |
| 二次轻推 | 静止后可对同一人再轻推一次 | 中 |
| 铁壁 | 本回合被撞时质量临时提高 | 低 |
| 吸地 | 提高本方摩擦，更快停下 | 低 |

### 7.3 释放时机

- **发球前**（选人后、松手发射前）点技能按钮；或  
- **自动被动**（满足条件即生效）  

一期推荐：**发射前点选主动技能**，规则最清晰。

---

## 8. 连携技

### 8.1 定义

同队两名（或三名）球员在短时间窗口内满足站位/碰撞条件 → 触发额外效果或演出。

### 8.2 第一期可做的连携（选 2～3 个）

| 连携 | 条件（示例） | 效果（示例） |
|------|--------------|--------------|
| 撞墙传 | 己方 A 撞己方 B，且 B 再碰到球 | 球额外吃一次小冲量 |
| 双人夹击 | 两名己方同时贴近对方同一人 | 对方下回合该人力量 - | 
| 门前配合 | 己方球员与球同在对方半场禁区附近 | 下一次射门力量微增 |

原则：条件用**已有物理事件**检测（碰撞对、区域），不要另做复杂 AI。

### 8.3 表现

- 简短文字 + 角色间连线光效即可  
- 避免长过场  

---

## 9. 分阶段内容范围

### 一期（正式可上线最小版）— 约 4～8 周量级（视人力）

**做：**

- Cocos 工程 + 微信小游戏构建跑通  
- 完整对局手感对齐原型（含弧线、预览、球门）  
- 本地双人 + 重开/结算  
- 球员 6～8 名，属性表生效，编队选 3  
- 主动技能 4 种，每人装 1 个  
- 连携 2 个  
- 极简大厅、教学引导（两指弧线必教）  
- 本地存档（解锁 1～2 人）  
- 基础音效 UI、适龄与隐私合规页  

**不做：**

- 实时联网 PVP  
- 抽卡大池、战斗通行证  
- 复杂 AI、天梯  
- UGC、观战、录像  

### 二期

- 简单 AI 对手（规则型：选最近球/门的人大力打）  
- 更多球员与技能  
- 每日挑战 / 简单排行（分数或胜场，可云开发）  
- 广告或少量内购皮肤（合规前提下）  

### 三期（可选）

- 异步或房间制对战（非帧同步优先）  
- 赛季、通行证  
- 更多连携与地图皮肤

## 10. 配置与数据（便于运营改表）

建议独立配置，热更或发版改：

```
players.json      # id、定位、五维、技能 id、解锁条件
skills.json       # id、类型、参数、次数、描述
combos.json       # 条件、效果、参与球员标签
physics.json      # 全局手感（从原型迁移）
stages.json       # 先到几分、场地皮肤（可后置）
```

## 11. 大厅与界面信息架构（手机）

1. **启动** → 合规/适龄 → 主页  
2. **主页**：开始对局 | 编队 | 图鉴 | 设置  
3. **编队**：3 个槽位选人、看属性与技能  
4. **对局**：比分、回合、技能按钮、弱引导  
5. **结算**：胜负、简单统计、解锁提示  

首局强制 30 秒内教学：选人 → 拖拽 →（可选）副指弧线 → 进球。

---

## 12. 变现与合规（先占位）

- 一期可不接入付费，先验证留存  
- 若变现：优先**皮肤/球衣**，慎动数值付费  
- 微信：用户隐私保护指引、软著/版号政策按当时类目要求准备（上线前单独核对）  

---

## 13. 风险与对策

| 风险 | 对策 |
|------|------|
| 迁移后手感漂移 | 原型与正式共用同一份 `physics.json`；双端对照验收清单 |
| 两指弧线难上手 | 教学关 + 单指也可弱弧（可选降低深度） |
| 技能破坏平衡 | 每局限次；只改倍率；先打表再做动画 |
| 范围膨胀 | 严格按一期清单；连携超过 2 个进二期 |

---

## 14. 验收清单（一期 Done）

- [ ] 微信开发者工具可完整打一局  
- [ ] 手感与 H5 原型主观一致（满力中场往返、弧线、换手）  
- [ ] 至少 6 名属性不同的球员可选 3 人上场  
- [ ] 至少 4 个主动技能可装配且有效  
- [ ] 至少 2 个连携可稳定触发并有提示  
- [ ] 教学覆盖蓄力与弧线  
- [ ] 本地存档解锁流程跑通  
- [ ] 竖屏真机双指无严重误触  

---

## 15. 近期执行顺序（建议）

1. 从原型导出 `physics.json` 手感表  
2. 建 Cocos 空工程，只迁「一场无技能对局」  
3. 对齐验收手感后再加 Roster / Skill  
4. 再加 Combo 与大厅  
5. 过微信构建与真机双指

## 16. 和当前仓库的关系

| 路径 | 角色 |
|------|------|
| `index.html` + `js/game.js` | 手感沙盒 / 设计参照 |

**文档结论：** 正式版 = **微信小游戏 + Cocos + 继承现手感**；内容第一刀只砍「小数值球员 + 少技能 + 两个连携 + 能上架的一局」；联网与重运营后置。
